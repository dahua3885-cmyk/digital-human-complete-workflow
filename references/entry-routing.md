# 入口路由与独立使用

## 路由原则

完整流程和拆开使用共用同一套阶段合同。拆开使用不是绕过上游，而是用“用户提供的可信外部输入”代替上游阶段产物，并如实建立外部交接物。

识别入口后，首次使用只发送简短安装完成提示，以及 [数字人完整流程](../数字人完整流程.md) 和 [开始使用前请先填写](../开始使用前请先填写.md) 两个可点击文件。用户填写资料文档后复制所选版本全文回传；收到后再用内部 [开工资料清单](../assets/preflight-intake-checklist.md) 判断本次必填项。只收“现在提交”的文件，后续敏感素材到相应阶段再收。任何入口在真人媒体处理前都必须完成合法使用声明和人物关系核验。

| 用户输入 | 入口模式 | 开始阶段 | 必须补做 |
|---|---|---|---|
| 视频链接、本地视频/音频、逐字稿，并要求二创或整条数字人 | `full` | 二创 | 来源取证、二创研究、创作者画像、文案确认 |
| 用户提供文案，并要求配音、数字人或整条成片 | `from_script` | 音频 | 冻结显示稿、创作者/读音信息、文案确认或“原样使用”声明 |
| 用户提供最终 WAV，并明确已确认 | `from_audio` | 数字人画面 | 声音授权、正文转写、媒体 QA、音频哈希和用户最终确认记录 |
| 用户提供现成数字人或单人口播 MP4，并要求包装 | `packaging_only` | 剪辑包装 | 视频授权、媒体 QA、转写、人物/主音频唯一真源与素材体检 |

用户只要求某一阶段时，任务订单把该阶段设为本次 `target_stage`，完成后停止。例如“只做声音”停在完整 WAV 与音频 QA；“只做数字人画面”停在画面确认；“只包装”不重新生成声音或人物。停止后必须保留当前阶段交接物，并显示“结束任务 / 继续下一模块”；用户选择继续时延长同一订单目标，不要求复制粘贴。

## 串联规则

- 每条视频只使用一个 `task-order.json`，四模块不各建一份互不相识的项目。
- 完整流程在每次用户确认后登记阶段交接物，下一阶段自动读取其路径和 SHA-256。
- 单模块完成后使用 `update_task_order.py ... extend --target <下一阶段>` 继续；图形界面按钮也必须调用同一转换。
- 外部输入只在入口处建立一次 `external-*-handoff.json`，进入流程后继续使用统一交接协议。
- 每个阶段或失败重试开始前必须先显示预计时间区间与依据。

## 完整流程的三个确认点

```text
二创稿 → 用户确认文案
完整 WAV → 用户实际试听并确认
完整数字人 MP4 → 用户实际观看并确认
确认后才进入下一阶段
```

“直接全部做完”不能取消三个确认点。包装代表性样片仍强制内部制作；是否等待用户确认可由用户要求决定。

## 外部输入交接物

外部输入没有本流程原生批准单时，建立：

- `external-script-handoff.json`
- `external-audio-handoff.json`
- `external-video-handoff.json`

至少记录：

```json
{
  "schema_version": 1,
  "source": "user_provided",
  "input_role": "script|audio|video",
  "path": "...",
  "sha256": "...",
  "provided_at": "ISO-8601",
  "user_instruction": "用户原话",
  "authorization_record": "consent-record.json 或等效证据",
  "technical_qa": "报告路径",
  "limitations": []
}
```

外部交接物只证明输入从用户处获得并完成当前检查，不得写成某个上游 Skill 已执行。

## 停止条件

- 用户拒绝合法使用声明，或者用途、人物关系、最终发布者含糊不清。
- 第三方声音/肖像只有公开素材、下载文件或口头转述，没有可验证授权。
- 请求涉及诈骗、身份冒充、索财/验证码、伪造官方/新闻/司法内容、删除生成合成标识或绕过安全审核。
- 输入主体或唯一真源不明确。
- 声音、肖像或视频使用权无法证明。
- 文案、音频或完整数字人画面尚未获得对应确认。
- 外部音频转写与用户声称的文案不一致。
- 外部视频不是稳定单人口播，或无法满足固定包装母版的最低裁切条件。
- 阶段 Skill 或其必读文件缺失。
