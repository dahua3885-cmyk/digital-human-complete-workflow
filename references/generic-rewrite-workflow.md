# 通用二创完整流程

## 定义

二创是基于同一问题重新研究、重新判断、重新组织的一条新内容，不是同义词替换、压缩摘要或逐段拼接。原视频负责锁定核心命题；同款高表现内容负责补充和替换；领域权威来源负责事实裁判；创作者资料负责让新稿属于这个人。

## 开工资料

先读取项目内 `creator-profile.md`。没有时让用户选择：

- [简洁版](../assets/creator-profile-quick.template.md)：5–10 分钟，适合先跑通；资料少时文案更偏通用。
- [专业版](../assets/creator-profile-pro.template.md)：适合长期稳定生产，能更准确贴合职业、案例、来源和表达指纹。

用户不想填表时可以逐题访谈或接收语音回答，由执行者整理后让用户确认。不能因为用户选择简洁版，就猜测其经历、资质或案例。

最低资料包：

- 职业/身份、服务对象与目标受众。
- 3 篇本人确认的文案，或累计 5–10 分钟本人真实口播转写。
- 真实可用案例、禁止虚构的经历与不可说的表述。
- 本领域优先事实来源和高风险边界。

专业版推荐资料包：

- 8–15 篇已确认文案或累计 20–40 分钟口播转写。
- 3–5 个可公开、可核验的真实案例。
- 常用术语表、事实来源表、偏好/禁用表达、CTA 与已确认改稿记录。

律师、医疗、金融等高风险领域不得把普通创作者的经验口吻直接迁移。只使用与创作者资质、执业范围和地域相符的事实；案例去标识化，不虚构胜诉、疗效、收益或客户结果。

## 输入路由

- 单条视频链接：解析真实链接、保存作品信息、下载、提取音频、转写、拆解、重构。
- 多条链接：逐条建立来源，先合并知识和互补信息，再设计新结构；禁止按来源拼段。
- 本地视频/音频：从媒体转写开始。
- 用户已给逐字稿：把逐字稿作为来源；不假装下载过视频。
- 用户直接给最终文案：不执行二创，但仍做显示稿冻结、事实风险提示和文案确认交接。
- 现有稿局部修改：只改点名范围；用户明确要求重写时才重跑全文。

## 1. 建立来源证据

1. 解析链接和作品 ID。
2. 保存账号、标题、发布时间、时长与公开互动数据快照。
3. 下载视频，提取音频并转写。
4. 对照发布文案、画面字幕和音频，校正姓名、机构、产品、法律条文、数字与专业术语。
5. 验证媒体非空、转写非空、链接与作品一致。失败时不得进入写稿。

## 2. 还原原视频

先写内部选题卡：

```text
原视频对象：
原视频核心问题：
原视频主要内容：
原视频结果承诺：
目标观众：
允许的同款边界：
排除的邻近方向：
```

完整还原开头承诺、知识点、步骤、案例、判断条件、证据、结尾及作者专属表达。教程必须保留“是什么、怎么做、看到什么结果、常见错误、怎样验收”。

## 3. 两条独立研究线

除局部改句外，每次新二创和全文重写都完成：

1. **同款高表现内容线**：寻找 1–3 条回答同一核心问题、公开表现可核验的内容，作为补充池和替换池。找不到足够精确候选时如实少交，不用泛相关内容凑数。
2. **领域权威事实线**：按行业使用一手权威来源。技术优先官方文档/论文；法律优先现行法律法规、司法解释、裁判文书与主管机关；医疗优先指南、监管机构与研究；金融优先监管披露和官方数据。

两条线不能互相替代。搜索词只能从原视频选题卡生成，不能用已经写出的二创标题反向定义原命题。

## 4. 来源贡献表

写稿前记录：

```text
原视频必须保留：
原视频可删除：
候选 A 提供：
候选 B 提供：
候选 C 提供：
权威事实纠错/补充：
创作者真实判断/案例：
最终保留：
最终替换或新增：
```

清单型内容默认从原视频保留约一半最有价值项目，再从候选共同池筛另一半；比例服从质量，但必须发生实质跨来源替换。非清单型内容保留知识主线，并至少替换或新增一个案例、解释角度、证据或判断模块。

## 5. 重构与成稿

先写重构决策，再写口播稿。至少在三层变化：

- 结构层：信息顺序、论证路径或清单组织改变。
- 内容层：新增事实、案例、判断、边界或候选贡献。
- 表达层：删除原作者专属词、比喻、句式、案例和引流链路。

使用创作者真实身份和受众能成立的表达，不虚构亲历。职业画像用于选择案例、证据和语气，不能偷换原视频命题。

## 6. 四项审核

1. 理解审核：没有误解或漏掉重要知识、步骤和结论。
2. 原创性审核：结构、内容和表达均发生实质变化。
3. 事实/专业审核：动态事实来自当前权威来源；专业主张符合创作者资质与领域边界。
4. 可制作性审核：文案中的界面、证据、案例和素材能真实取得并用于后续包装。

输出：来源与逐字稿、拆解与重构、干净口播稿、原创性与事实审核、修改记录。用户明确确认最终口播稿后才进入音频。

## 7. 反馈学习

每次改稿记录修改对象、原版本、确认版本、原因、影响范围和以后检查项。单条事实只留当前任务；稳定偏好写入本地 `creator-profile.md`；不得把未经用户确认的推测写成人物长期风格。
