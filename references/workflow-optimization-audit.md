# 当前流程缺陷与优化优先级

本文件不重复介绍已有流程，只记录仍会影响首次成功率、返工和开源适配的问题。

## 已在 0.5–0.8 修正

### 1. 安装告知与项目开工混在一起

原问题：所有资料都在每条项目开工时询问，用户会感觉反复填表、做到中途才被要求录声音和形象。

修正：第一次调用建立长期本地资料库；每条视频只补项目变化。完整要求一次告知，敏感文件分阶段提交。

### 2. 所有用户被同一套完整资料阻塞

原问题：只做二创或包装的人也可能被要求完成声音和形象建档。

修正：四个模块独立激活。未选择模块为 `not_selected`，不阻塞无关入口；进入该模块前才要求 `ready`。

### 3. 数字人音频把“像不像”与“风格选择”混在一起

原问题：参考声本身不合格时，三版速度都可能不好，用户会在错误基础上选风格。

修正：先做参考声 QA 和身份保持测试，通过后才做三风格；三风格采用 A/B/C 盲听，最后用新文案独立验证。

### 4. 建档选择每条重复

原问题：用户每条视频都可能重新回答风格和素材问题，增加决策疲劳且破坏账号一致性。

修正：声音、形象、创作者和品牌 Profile 持久复用，仅在组合变化确实需要重新校准或复核时建立新版本；旧 Profile 保留为历史。

### 5. 独立模块与完整流程没有真正连接

原问题：四个模块虽可分别调用，但没有同一任务订单和继续下一模块的转换，容易迫使用户复制粘贴文案或重新上传音频。

修正：新增本地资产中心、`task-order.json`、路径+哈希交接和 `extend` 操作。完整流程确认后自动续接；单模块完成后可以在同一订单继续下一模块。

### 6. 把版本不一致误写成文件失效

原问题：修改上游内容后把所有旧文件称为失效，容易让用户误以为文件损坏或严格执行仍会失败。

修正：旧文件保留为 `historical`，当前任务仅标记 `needs_update`；只有直接输入内容哈希变化才要求下游更新。

### 7. 没有强制逐阶段估时

原问题：只在项目开工时笼统估算，失败重试没有新增时间说明。

修正：任何阶段开始或重试前必须写入时间区间和依据；信息不足时先检测或小样，禁止编造数字。

### 8. 缺少模块反馈沉淀和实际界面

原问题：反馈散落在聊天里，用户看不到四类资产、阶段串联和继续动作。

修正：四模块各建反馈文件并区分适用范围；二创交付明确提供可复制文案，阶段只显示简单估时，离线与质量待优化使用不同状态。按用户最新决定不提供可视化工作台。

## 仍需优先优化

### P0：正式开源前

1. **其余资产就绪状态自动计算**：创作者资料已经由 `save_creator_profile.py` 确定性校验并同步更新；声音、形象和品牌仍需根据授权、素材与 QA 证据自动计算，避免人工把内部状态写错。
2. **四阶段适配器落地**：0.9.8 已交付并默认绑定二创、Chatterbox 声音、MuseTalk 画面和固定包装四个公共阶段。总控仍不能把安装包校验通过当成当前电脑的四阶段预检通过；大型模型、GPU、FFmpeg 和授权素材必须在开工前分别验证。
3. **媒体预检脚本**：自动检查参考声和人物视频的时长、格式、帧率、硬切、多人、脸部漂移、响度、削波和静音；当前规范完整，但执行仍依赖各阶段 Skill。
4. **完整公开演示**：至少用一套可再分发素材跑通完整流程、文案入口、音频入口和包装入口，并公布预期文件树、运行预检、耗时和已知缺陷。
5. **许可证决策（已完成）**：编排层采用 Apache-2.0；人物声音、肖像、姓名、品牌和第三方模型/服务不在该许可授权范围内。

### P1：降低返工

1. **自适应估时**：把每次真实耗时按阶段、输入规模、模型、硬件和重试原因回写本地历史，使下次时间区间逐步收窄。
2. **风险句优先机制**：文案确认后自动提取最长句、英文/数字句、CTA和高风险事实句，先验证这些，再生成全量音频和画面。
3. **跨阶段变更影响预览**：用户改一句文案前先比较内容哈希，提示哪些当前版本需要更新；不把旧文件称为损坏。
4. **质量分数与硬门槛分开**：硬性拒收项直接停止；非阻断问题显示分数和建议，避免“有一点噪声就全盘拒收”或“总分高却遮嘴”的错误判断。
5. **成本与时间预估**：开工前按文案时长、模型、显存和入口给出区间；重试前显示预计新增成本。

### P2：长期社区质量

1. **Profile schema 迁移**：版本升级时自动迁移旧状态和交接物，不让早期用户重新建档。
2. **匿名问题包**：一键导出不含文案、声音、肖像、链接和密钥的诊断包，方便开源 Issue 排错。
3. **适配器兼容测试**：社区提交声音/形象/包装适配器时，自动运行授权闸门、哈希链、确认点和交付清单测试。
4. **反馈回流范围**：每次修改区分“本条修正、系列偏好、长期人物规则”，防止一次偶然意见污染整个创作者 Profile。

## 推荐的目标体验

```text
安装 Skill
  → 第一次调用：打开两份文档，选择简洁版或专业版并建立本地长期资料库
  → 默认只确认建档成功；用户询问或任务确有缺口时显示中文准备情况
  → 用户给链接或文案
  → 自动生成本条 task order、逐阶段预计时间与成本
  → 二创确认
  → 风险句试听 + 完整数字人音频确认
  → 画面样片内部 QA + 完整画面确认
  → 固定剪辑包装 + 封面 + 最终验收
  → 稳定反馈写回长期 Profile
```

这个目标不是减少必要确认，而是让确认发生在正确位置，并让用户只回答真正变化的内容。
