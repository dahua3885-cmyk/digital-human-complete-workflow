# 数字人音频｜首次建档与每条生成

本文件把“首次建立一个人的数字人声音”和“以后为每条视频生成正式音频”分开。第一次建档做完整校准；以后复用已确认 Profile，但每条完整音频仍要用户试听确认。

## 不可误解的硬规则

- A/B/C 三风格只在首次建立有效声音 Profile 时选择一次。
- Profile 有效期间，每条新视频自动沿用 `selected_style`，不再次询问、不再次生成三风格。
- 每条视频的完整音频仍要试听确认；这是检查该条发音和生成质量，不是重新选择长期风格。
- 只有人物、模型、参考声、语言变化导致原参数不再适用于当前组合，或用户明确要求长期更换风格并创建新 Profile 版本时，才重新三选一；旧 Profile 仍保留为历史记录。

## A. 首次声音建档

### A1. 确认人物、用途和引擎

- 确认声音属于本人或已有可验证的第三方声音授权。
- 记录语言、主要内容类型、发布平台和商业用途。
- 确认绑定的声音 Skill、模型和版本；读取其参考音频限制。通版要求不能替代模型的硬格式要求。

### A2. 先指导录制，再接收参考声

发送 [声音参考录制指南](../assets/voice-recording-guide.md)。通用建档建议录制 2–5 分钟干净母素材，目的是建立可复用素材库，不是声称所有模型都要求这么长。模型适配器从中选择其实际需要的连续片段。

### A3. 参考声体检

生成 `voice-source-qa.json`，至少记录：

- 文件、SHA-256、时长、格式、采样率、声道和位深。
- 是否只有一个说话人，是否存在音乐、混响、环境噪声、削波、爆音、断句拼接或强降噪伪影。
- 有效语音比例、静音、峰值、响度和可懂度。
- ASR 转写及错词；参考声与授权人物是否一致。

严重失真、多说话人、背景音乐、持续混响、身份无法确认或授权不完整时拒收。不要依靠强降噪把根本不合格的素材伪装成合格参考声。

### A4. 模型适配片段

- 按声音 Skill 的要求从母素材选择连续片段，不跨句硬拼。
- 保存所选区间、模型、前处理方式和片段 SHA-256。
- 先生成一段身份保持测试；音色明显不像、吞字或不稳定时退回选段/录制，不继续做风格试听。

### A5. 准备同一份校准文案

校准文案建议 20–40 秒，包含：

- 短句、中句、长句和自然收句。
- 数字、日期、并列和转折。
- 本赛道常见英文、品牌或缩写；先按发音核验流程完成中文语境研究。
- 不包含敏感身份主张、夸张承诺或本次才成立的动态事实。

三种候选必须使用完全相同的文案、参考声和模型版本。

### A6. 三风格盲听

先以 A、B、C 随机顺序交付，避免“正常版”“短视频版”等名称影响选择：

- `natural-balanced`：自然均衡。
- `steady-integrated`：稳健融合。
- `short-video-compact`：短视频紧凑。

用户记录：最自然、最像本人、最适合长期账号、太快/太慢的具体句子。选定一个基础风格后才揭示风格名称。可以在所选风格内微调短/中/长句，但不能把三份剪拼成没有规则的第四版。

### A7. 独立验证

换一段未参与选择的 30–60 秒验证文案，生成完整音频并检查：

- 音色身份、短中长句节奏、句末完整度。
- 数字、英文、品牌和专业词。
- 是否有吞字、重复、爆音、断裂、异常静音和音量跳变。
- ASR 与冻结显示稿的一致性。

用户明确试听确认后，才能冻结 `voice-profile.json`。

### A8. 冻结内容

至少保存：人物匿名 ID、声音 Skill/模型版本、参考片段哈希、所选风格、短中长句适配值、停顿策略、响度边界、发音词典、三份候选和验证样本哈希、用户确认原话与时间。

## B. 每条视频的数字人音频

1. 接收并冻结最终显示稿；未确认文案不得生成正式音频。
2. 提取新增的英文、数字、品牌和专业词，更新本条发音研究；长期词典已有内容仍放回上下文复核。
3. 建立 TTS 稿，只改发音、数字和停顿，不改屏幕显示稿语义。
4. 根据已冻结 Profile 对短/中/长语义块选择模型适配参数。
5. 先生成风险句试听：开头、最长句、英文最多句、数字句和 CTA。
6. 风险句通过后生成完整音频；记录分段、seed/模型参数、重试和拼接关系。
7. 完成 ASR 对稿、响度/峰值、静音、重复、吞字、爆音和连续试听 QA。
8. 用户实际试听完整音频并明确确认；只确认样本不能代替完整音频确认。
9. 写入音频批准单和 `audio-handoff.json`，绑定最终 WAV SHA-256。

## C. 需要重新建档的变化

- 人物、参考声或授权主体变化。
- 声音模型、权重、版本、核心采样路线或参数语义变化。
- 新语言、明显不同的表演风格或长期账号定位变化。
- 用户持续反馈音色不像或节奏不适合，且不是单条文案造成。

只是换一条文案，不应重新进行三风格选择。
