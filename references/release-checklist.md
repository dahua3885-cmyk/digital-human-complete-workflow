# 开源与成片验收表

## A. 发布 Skill 包前

- [ ] `SKILL.md` 描述能准确触发完整流程，也明确它只是编排层。
- [ ] 四个阶段通过 Profile 绑定，没有把某个作者、声音模型、人物资产、品牌或平台写成公共默认。
- [ ] `full / from_script / from_audio / packaging_only` 四种入口都已定义，拆开使用仍建立外部输入交接物。
- [ ] 包内没有真人参考声、肖像母片、Cookie、令牌、客户数据、私有素材或机器绝对路径。
- [ ] 示例 Profile 可通过 `validate_workflow_profile.py`。
- [ ] `distribution-manifest.json` 列出全部关键内部文件；在干净复制目录运行 `verify_distribution.py` 出现 `DISTRIBUTION_OK`。
- [ ] `runtime-config.example.json`、四阶段适配器合同和 `preflight_runtime.py` 都存在；缺阶段Skill/模型/命令时明确阻断。
- [ ] 只有四个启用阶段全部通过运行预检和公开演示时，才把发行状态标记为端到端可运行。
- [ ] 对干净发行副本运行 `verify_distribution.py`，并完成 TODO、占位绑定和未完成脚手架扫描；只有 `DISTRIBUTION_OK` 且无发布阻断项时才能正式发布。
- [ ] 现有二创、声音、画面、包装 Skill 均未被修改。
- [ ] 简洁版与专业版创作者资料模板都可用，且说明资料量对适配质量的影响。
- [ ] 首次声音建档包含三种风格试听与一次明确选择，英文/品牌/缩写存在中文语境在线发音核验闸门。
- [ ] 声音风格作用域为 `once_per_valid_voice_profile`，`voice_style_reprompt_each_project=false`；每条视频只复用风格并确认该条完整音频。
- [ ] 数字人素材录制前检查清单存在，授权资料默认本地私有存储，公共包不要求上传到维护者云端。
- [ ] 开工资料清单在首次交互一次性说明所选入口的全部后续资料，同时仍按阶段最小化收集敏感文件。
- [ ] 首次调用检查 `onboarding-status.json`；创作者资料未建档时进入资料版本选择，已建档时直接接受全流程或任一独立模块任务。
- [ ] 首次客户引导不要求“数字人全流程 / 分别制作”二选一；只发送简短安装完成提示和两个可点击文档，不在聊天中展开手册或资料表正文。
- [ ] 简洁版和专业版资料表末尾均要求用户填写后复制所选版本全部文字并发送回聊天。
- [ ] 创作者资料确认后明确告知两种使用场景同时可用；只有实际任务开始时才识别本次入口。
- [ ] `asset-center.json` 索引长期创作者、声音、形象和包装 Profile；不保存原始真人媒体、证件或密钥。
- [ ] 二创、数字人音频、数字人形象、剪辑包装各有独立反馈文件；每条反馈区分仅本条、系列偏好和用户确认的长期规则。
- [ ] 品牌资料只包含账号/品牌名称、Logo、授权字体与颜色、固定 CTA、必要声明、封面素材及授权；允许个人创作者留空不适用项。
- [ ] 长期创作者、声音、形象、品牌资料与每条视频资料分离；需要重新校准时建立新版本并保留旧 Profile。
- [ ] 单模块与完整流程都创建一个 `task-order.json`；阶段通过路径+SHA-256自动交接，用户不复制粘贴。
- [ ] 单模块完成后可用同一订单延长到下一模块；完整流程在三个用户确认后自动续接。
- [ ] 每个阶段显示简单的大致时间区间；网络异常只显示网络提示并禁用生成，质量不高显示待优化，不称文件损坏。
- [ ] 二创完成区在“结束任务”旁提供一键“复制文案”，复制内容与已确认文案一致且不改变任务状态。
- [ ] 确认发行包不包含可视化工作台；复制文案、继续阶段、简单估时和离线提示均由总控 Skill 的交付消息与任务订单表达。
- [ ] 安装包根目录包含 `数字人完整流程.md` 和 `开始使用前请先填写.md`；首次调用用 `prepare_first_use_docs.py` 把最新版复制到当前活动工作区并只链接工作区副本；不得直接链接 `.codex/skills/`。初始化后的正式用户工作区也有两份留存文档，并在 `forms/` 生成简洁版、专业版和授权声明。
- [ ] 首次客户回复逐字匹配 `SKILL.md` 的固定三段欢迎语，唯一动态内容是两个已经验证存在且位于当前活动工作区内的绝对文件链接；回复中不含版本号、`draft`、发行校验、工作区状态、运行配置、阶段绑定或端到端状态。
- [ ] 简洁版包含受众常见问题、3–5个内容方向、内容目标、可公开真实材料、禁用项和专业边界，并为不易理解的字段提供示例；专业版不要求同时填写简洁版。
- [ ] 用户完整回传任一版本后直接建档，不要求“确认按此建档”，不追加第二套问卷；“无 / 暂无”按有效答案处理，动态事实核验和本机长期保存采用默认规则。
- [ ] 客户资料页不显示“简洁版默认设置 / 专业版默认设置”等内部规则；可复制填写框只放短字段并按信息组分段，解释和示例放在填写框外。
- [ ] 二创文案、音频确认和画面确认后，分别使用一级 Markdown 大标题询问是否继续下一模块；标题不得埋入普通段落。
- [ ] `create_task_order.py` 与 `update_task_order.py` 的创建、开始、完成、失败、继续下一模块和 `needs_update` 路径均通过测试；缺用户批准的文案/音频/画面交接不能越级完成。
- [ ] `init_user_workspace.py` 能建立本地私有目录、模板和模块状态，拒绝覆盖非空目录或已有建档。
- [ ] 合法使用与授权声明、第三方证据门槛、高风险阻断和滥用响应均已定义；免责声明没有写成绝对免责。
- [ ] 公共文档区分纯本地开源、社区支持、代制作与托管服务，不把低风险模式的边界套用到后两者。
- [x] 已选择并加入 Apache-2.0 开源许可证；当前版本仍因通用阶段执行器和端到端演示未完成而标记为公开预览版。
- [ ] 四个通用阶段Skill或固定版本公共安装源、模型/服务获取方式、硬件要求与许可证已经随发行说明提供；不得引用作者私人D盘、参考声或肖像。
- [x] 对外文档说明：用户必须自备合法授权的声音、肖像、模型、素材和四个兼容阶段 Skill。
- [x] 代码许可证没有误授权维护者本人或他人的声音、肖像、姓名、账号品牌和商标；公共演示不使用未单独授权的真人身份资产。
- [ ] 公共包只称“剪辑包装”，没有向用户暴露历史版本编号、内部母版名称或版式选择。

## B. 每次完整任务开工前

- [ ] `skill-contract.md`、`project-brief.md`、`workflow-profile.json` 和 `task-order.json` 已建立。
- [ ] 用户已在开始时看到按入口标注的完整资料清单，并选择简洁版或专业版创作者资料。
- [ ] 合法使用声明已明确确认；用途、人物关系、最终发布者和平台完整。
- [ ] 第三方人物授权证据可验证；高风险身份/场景已停止或完成适用法律专业复核。
- [ ] 人物、声音、肖像、发布用途和素材授权有明确证据。
- [ ] 已用简洁版或专业版建立 `creator-profile.md`；二创需要的最低人物资料包完整，高风险职业的专业边界与权威来源已记录。
- [ ] 已建立 `consent-record.json` 或等效证据，声音和肖像分别取得明确授权。
- [ ] 四个阶段 Skill 可发现，并已记录名称、版本或 `SKILL.md` 哈希。
- [ ] 输入真源与输出目录明确；私有资产不会写入开源包。

## C. 阶段交接

- [ ] 二创阶段有来源、重构、干净口播稿与 QA，且最终稿已经用户确认。
- [ ] 音频阶段有完整音频、转写、QA 与真实试听确认；批准单绑定最终音频 SHA-256。
- [ ] 当前人物/模型/参考声/语言使用独立 `voice-profile.json`，没有复用他人的固定语速倍数。
- [ ] 首次声音建档包含录制前指导、参考声 QA、身份保持测试、A/B/C 三风格盲听、独立验证与 Profile 冻结。
- [ ] 首次建档已生成同文案三风格样本，用户选定一个 `style_id`；英文、品牌和缩写已有可听中文语境来源或用户确认记录。
- [ ] 画面阶段验证音频哈希，完成代表性样片和阶段 Skill 要求的口型/动作/接缝/封装 QA。
- [ ] 用户录制前已收到检查清单并知悉；真人参考视频达到至少 30 秒连续合格素材，推荐为 60–90 秒，并通过单人、固定机位、脸部清晰、无遮挡、无硬切和静态背景体检。
- [ ] 用户已经观看并明确确认完整数字人 MP4；确认原话和文件哈希写入画面交接物。
- [ ] 包装阶段有文案语义表、口播触发点表、素材真源表和代表性内部样片。
- [ ] 所有交接物都引用阶段原生制品和哈希，没有复制后重新修改。
- [ ] 上游内容变化时只把直接依赖的当前版本标记为 `needs_update`；旧文件仍作为 `historical` 保留。

## D. 最终文件验收

- [ ] 被绑定包装 Skill 规定的无封面母版、带封面发布版、9:16/3:4/1:1 封面、字幕、音频、工程和 QA 制品全部存在；不适用项有合同依据。
- [ ] 对最终文件本身完成媒体参数、时长、音轨、首尾帧、字幕、触发同步、素材证据和连续播放检查。
- [ ] `delivery-manifest.json` 列出全部必交文件的路径、SHA-256、字节数、媒体参数和 QA 状态。
- [ ] 上游与最终音轨/字幕/画面之间的追溯链完整。
- [ ] 发布阻断项全部关闭；非阻断限制已经在交付说明中披露。
- [ ] 发布版保留适用的生成合成显式/隐式标识，平台发布时主动声明。

任一必交项缺失时，只能报告当前已完成阶段，不能称为完整流程或最终版。
