# 0.8 剩余明显 Bug 审计

## Bug 1：通用阶段执行器尚未全部交付

0.9.5 及以前没有随附可在不同用户电脑上复现安装的二创、声音、画面和包装执行器，却只测试了任务路由，导致用户进入画面阶段后才发现默认仍是示例 Skill。0.9.6 加入了画面阶段调用器，但引擎源码仍需安装后另外获取。0.9.7 已把固定 MuseTalk 1.5 公开推理源码、便携兼容层、许可证、依赖、固定 revision 模型下载、迁移、运行检查与渲染器随总包交付；声音与包装等其余生产执行器仍未全部交付。总控协议不能替代模型、服务或阶段 Skill。

修复标准：所有阶段通用适配器随发行提供，能读取统一交接物、返回质量状态和简单预计时间，并通过公开演示。任何默认 Profile 出现 `your-*` 的已启用阶段时，发行校验必须失败，不能只给警告。

## Bug 2：资产就绪和媒体体检还没有统一自动计算

资产卡仍可能依赖人工更新；参考声、人物视频和外部媒体的时长、响度、削波、硬切、多人、遮嘴和脸部漂移仍由不同阶段 Skill 分散检查。

修复标准：提供统一状态计算器和媒体预检器，把通过、待优化、需补资料、网络异常和技术阻断写回资产中心与任务订单。

## Bug 3：反馈沉淀与资产版本更新仍依赖人工

四类反馈文件已经分开，并区分仅本条、系列偏好和长期规则，但长期规则写回 Profile、冲突检测和历史版本保留仍依赖执行者正确操作。

修复标准：增加确定性的反馈升级脚本；只有用户明确确认的长期规则才能写回 Profile，并自动保存变更前版本、来源任务和生效时间。
