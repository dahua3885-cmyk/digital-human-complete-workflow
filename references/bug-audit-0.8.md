# 0.9.8 主动 Bug 审计

审计日期：2026-09-01。

## 本次已修复

1. **示例阶段被当作真实引擎**：默认 Profile 和运行配置改为四个随包公共阶段；发行校验拒绝占位绑定。
2. **安装完成却制作不了画面**：随包安装 MuseTalk 公共阶段；预检明确检查 CUDA、Python、FFmpeg 和全部模型；已有环境可补齐缺失模型。
3. **空检查或手工 `ready` 造成假就绪**：总控预检必须实际执行每个阶段的 `check_runtime.py`，不信任手工布尔值。
4. **空 JSON 或其他任务文件可把订单标为完成**：所有阶段交接现在强制校验任务编号、阶段 Skill、状态、真实文件、SHA-256、上游交接和用户确认。
5. **授权只是示例文档，没有执行闸门**：新增授权保存与校验脚本；进入声音、肖像合成前必须验证合法使用、权限和证据。
6. **客户看到英文状态**：客户状态与资料建档只输出固定中文；内部枚举不直接展示。
7. **网络或依赖失败泄漏长堆栈**：安装器捕获外部命令错误，输出中文原因并支持安全重试。
8. **嵌套 Skill 被重复发现**：仓库内阶段源使用 `STAGE.md`，安装时才原子转换为独立 `SKILL.md`。
9. **声音与包装仍是缺失模块**：新增 Chatterbox 中文声音阶段和固定竖屏包装阶段，均含准备器、检查器与执行器。
10. **已有 MuseTalk 环境少一个模型就卡死**：新增 `--repair-existing-models --accept-large-download` 修复入口。

## 仍需持续观察但不阻断安装

- GPU、显存、驱动和网络差异无法由 GitHub 包消除，必须由阶段预检判断。
- 首次声音与画面模型下载体积较大，下载中断后应复用已有分片重试。
- AI 二创质量和真人口型效果属于质量差异，不应显示为“文件损坏”；仍需按阶段 QA 和用户确认处理。
- 反馈自动升级为长期规则仍需用户明确确认，不能自动学习并覆盖个人 Profile。
