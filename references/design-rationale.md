# 通版设计说明

## 产品形态

这不是一条只能从头跑到尾的流水线，而是“一个总控、两种用户场景、四个内部阶段、四种内部入口、三个用户确认点”。数字人全流程和分别制作始终同时可用，不是套餐二选一；用户实际发起任务时才识别本次场景。分别制作只展示二创文案、数字人、剪辑包装三个选项，其中“数字人”在内部再根据用户输入路由到文案入口或音频入口。

```text
视频链接/本地视频 ─→ 二创 ─→ [确认文案] ─→ 音频 ─→ [确认音频]
用户最终文案 ────────────────────────────────┘
用户最终音频 ─────────────────────────────────────────→ 数字人画面 ─→ [确认画面]
用户现成口播视频 ─────────────────────────────────────────────────────────→ 剪辑包装
```

完整流程逐段执行；拆开使用从可信外部输入进入。外部输入建立独立交接物，不假装上游阶段已经运行。

## 0.8 定案

### 风格选择与逐条音频确认分离

- 三风格只在每个有效声音 Profile 首次选择一次，普通新视频不再询问。
- 每条视频仍确认完整音频，但只检查这条的发音和生成质量，不改变长期风格。
- 长期换风格通过新版本 Profile 生效，保留旧版本和生效时间。

### 发行完整不等于端到端可运行

- 发行清单与校验脚本保证总控内部文件不缺失。
- 运行预检保证阶段Skill、命令、模型/服务配置存在。
- 当前四个专用阶段实现绑定作者个人资产和机器路径，不能原样公开；0.8明确标记不含端到端运行时。
- 四模块通过同一 `task-order.json`、路径+哈希交接和可延长目标阶段串联，不要求用户复制粘贴。
- 上游内容变化使用 `needs_update` 和历史版本语义，不把仍可播放的旧文件称为损坏。
- 任何阶段或失败重试前必须展示有依据的时间区间。
- 四个模块各有独立反馈文件，只有用户明确确认的长期规则才写回未来任务。
- 用户界面只显示简单阶段估时；网络异常禁用生成，质量一般标记待优化。

### 首次启用代替每条重复收集

- 安装不自动执行代码或上传个人资料；第一次调用时检查本地 `onboarding-status.json`。
- 用户首次只选择基础信息简洁版或专业版。四个模块独立就绪，声音、形象和包装资料在第一次实际使用对应模块时再补，不要求所有人预先完成完整数字人资料。
- 创作者、声音、形象、品牌进入长期本地资料库；每条视频只补来源、用途、动态事实和本条素材。

### 数字人音频拆为两个周期

- 首次建档：录制指导、授权、参考声 QA、身份保持测试、A/B/C 三风格盲听、独立验证、冻结 Profile。
- 每条生成：冻结文案、发音研究、风险句试听、完整生成、ASR/音频 QA、用户确认和哈希交接。
- 只有人物、模型、参考声、语言或核心表演风格变化才重新建档，不因普通换稿重复三选一。

### 0. 开工一次说明、资料分阶段提交

- 用户一开始就能看到从当前入口到目标终点全部会需要什么，不会做到音频后才突然得知还要录人物样片。
- 为降低敏感数据暴露，清单一次说明，但声音、肖像和品牌资产仍到对应阶段再提交。
- 在任何真人媒体处理前完成合法使用声明；第三方人物必须提供可验证的分项授权。

### 0.1 开源维护者边界

- 纯本地开源、不接收素材、不提供算力、不代制作，是相对低风险的默认形态，但不能宣称绝对免责。
- 代制作、远程调试、云端/API 是不同角色，需承担相应授权核验、内容处置、个人信息和服务治理义务。
- 标准开源许可证不能限制特定用途；若把禁止用途写成许可条件，应如实称为“源代码可用”而非 OSI 意义的开源。

### 1. 参考视频先提醒、后录制

- 执行者在用户录制前发送可复制的检查清单，而不是素材上传后才告知要求。
- 最低可用为体检后 30 秒连续合格素材；正式推荐 60–90 秒；高频使用可录 90–120 秒主模板和备用模板。
- 更长只在素材合格时增加动作选择、降低重复感，不是官方保证，也不会自动提升口型质量。
- 黑色背景不是硬要求；静态、整洁、低干扰才是核心。动态背景、多人、镜头运动、遮脸和光线跳变拒收。

### 2. 授权资料本地优先

- 开源使用者默认把授权、声音和肖像资料放在自己的私有项目或自建存储中，不上传给开源维护者。
- 公共运行记录只保存匿名对象 ID、证据类型和哈希，不保存证件、姓名或可直接访问链接。
- 集中云端属于独立 SaaS，需要租户隔离、加密、留存/删除、撤回、审计、处理者协议和法律复核，默认不开启。

### 3. 创作者资料双档

- 简洁版：六个必答问题，适合 5–10 分钟快速起步；资料少时文案更偏通用。
- 专业版：身份资质、受众、来源层级、真实案例、表达指纹、样本、栏目和长期反馈，适合长期稳定生产。
- 两种都允许访谈代填，但答案必须由用户确认；不能用 AI 猜测职业经历。

### 4. 首次三风格声音确认

- 自然均衡：从模型默认节奏起步，广泛适用。
- 稳健融合：保留当前专用流程的听感逻辑，短句略慢、长句连贯、收句明确；固定倍率不进入公共默认。
- 短视频紧凑：整体更利落但不赶读。它是实用预设，不宣称为有统计依据的“最多人使用”。
- 用户第一次只选一次，后续在同一人物、模型、参考声和语言组合上沿用；组合变化则重校准。

### 5. 英文发音硬闸门

英文、品牌、缩写和模型名必须联网寻找中国人真实可听的读法。优先官方中文内容，其次可靠中文行业媒体，再次是多名高质量从业者。搜索摘要不算发音证据；来源冲突时让用户从完整原句试听中确认并写入词典。

### 6. 唯一剪辑包装

公共流程只称“剪辑包装”：1080×1920、人物右下、黑色背景、青蓝强调、单行字幕，并固定交付无封面版、带封面发布版和 9:16/3:4/1:1 三张独立封面。公共界面不出现历史编号或版式选择。

## 公共层与私有层

| 开源公共层 | 本地私有层 |
|---|---|
| 两种用户场景、四种内部入口、状态机、确认点 | 创作者身份、职业和受众 |
| 通用二创研究和审核流程 | 真实案例、客户资料、禁用项 |
| 三风格声音校准协议 | 参考声、模型权重和发音词典 |
| 参考视频录制与体检 | 真人视频、循环候选和肖像授权 |
| 固定剪辑包装与封面规范 | 品牌名、人物封面图、Logo 与路径 |
| 哈希、批准单、版本一致性矩阵 | Cookie、令牌和机器环境 |

## 现有专用 Skill 的处理

现有二创、声音、画面和包装 Skill 原样保留。总控通过本地私有 Profile 绑定它们；进入某阶段时重新读取并完整执行原 Skill。专用参数仍只服务原人物，不进入公共默认。

若本地包装 Skill 内部仍使用历史版式名称，适配器在内部绑定到“竖屏右下人物、黑色背景、青蓝强调”的实现；公共用户不需要看到或选择内部编号。

## 发布边界

当前版本为 `0.9.1-draft` 公开预览版，代码与文档采用 Apache-2.0。首次客户文档已经改为在调用时复制到当前活动工作区，避免直接链接 Skill 安装目录导致文件查看器拒绝打开。发布四个通用阶段 Skill 或固定安装源、补齐资产中心就绪状态自动计算、反馈升级脚本和通用媒体预检、完成资料回传、全流程及三个独立模块入口与滥用阻断行为测试，并用不含真人隐私的演示项目通过端到端预检后，才适合标记为正式可运行版本。
