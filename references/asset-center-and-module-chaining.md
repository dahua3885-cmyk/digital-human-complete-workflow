# 数字人资产中心与四模块串联

## 资产中心是什么

资产中心不是把真人声音和肖像上传到维护者云端，而是用户工作区中的本地索引：`profiles/asset-center.json`。它连接四张长期资产卡：

| 资产卡 | 保存内容 | 原始敏感素材 |
|---|---|---|
| 创作者 | 职业、受众、表达、案例、专业边界 | 不需要真人媒体 |
| 数字人音频 | 声音 Profile 版本、长期风格、模型/参考声哈希、授权状态 | 只保存在 `.private/voice/` |
| 数字人形象 | 人物模板版本、参考视频哈希、素材 QA、肖像授权状态 | 只保存在 `.private/avatar/` |
| 剪辑包装 | 固定布局、Logo、字体、CTA、封面和品牌素材状态 | 按用户本地路径引用 |

资产中心只保存 Profile 路径、版本、状态和哈希，不复制声音、肖像、证件、密钥或原始视频。允许状态为 `ready / pending / needs_recalibration / needs_review / not_selected / blocked`。

## 四个模块怎样自动串联

每条视频只建立一个 `task-order.json`。订单包含入口、目标、当前阶段、四阶段状态、预计时间、失败原因、交接物和下一动作。

```text
视频链接
  → 二创输出 script-handoff.json
  → 用户确认文案
  → 同一订单把该路径和 SHA-256 登记为数字人音频输入
  → 数字人音频输出 audio-handoff.json
  → 用户确认完整音频
  → 同一订单登记为数字人画面输入
  → 数字人画面输出 avatar-handoff.json
  → 用户确认完整画面
  → 同一订单登记为剪辑包装输入
```

交接只传“文件路径 + 内容哈希 + 用户确认 + QA + 授权引用”，不重新复制文案、音频或视频。下一阶段开始前重新核对哈希，所以不会把另一条任务的文案或音频串错。

## 单独使用后怎样继续

- 用户只做二创：订单的入口和目标都设为 `rewrite`。二创完成后订单结束，同时保留 `script-handoff.json`。
- 用户随后选择“继续生成数字人音频”：不新建文案、不复制粘贴。把同一订单的目标延长到 `voice`，原 `script-handoff.json` 自动成为输入。
- 音频、画面也按同样方式延长到下一阶段。
- 用户直接从文案、音频或视频开始时，为外部输入建立一次外部交接物，再进入同一订单机制。

命令行协议：

```powershell
python scripts/create_task_order.py <工作区> --project demo --entry rewrite --target rewrite --source-kind url --source <视频链接>
python scripts/update_task_order.py <task-order.json> extend --target voice
```

在 Codex 对话里，总控 Skill 在用户确认后自动执行这次状态转换；未来做 Web/桌面应用时，“继续生成音频”“继续生成画面”“继续剪辑包装”按钮调用同一个 `extend` 操作。按钮不是另一套流程。

## 模块卡片应该显示什么

每张模块卡固定显示：

- 长期资产是否就绪、缺什么、是否需要重新校准。
- 当前任务是未开始、运行中、等待确认、需更新、完成还是失败。
- 本次输入来自外部还是上一个模块，路径和哈希是否匹配。
- 开始/重试预计时间、估算依据和最近一次真实耗时。
- 失败原因、是否安全重试和下一步。
- 本模块独立完成后的“结束任务”与“继续下一模块”动作。

Skill 包提供的是数据结构、路由和状态转换。要出现真正可点击的卡片和按钮，还需要在其上开发 Web/桌面界面；不能把 Markdown 说明称为已经完成的应用。
