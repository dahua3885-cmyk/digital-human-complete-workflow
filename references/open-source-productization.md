# 开源产品化路线

> 当前公开预览版采用 Apache-2.0；许可证已经确定，但四个通用阶段执行器和端到端公开演示仍是正式版阻断项。

目标不是让用户“能跑一次”，而是让不同职业、不同电脑和不同模型环境的人知道从哪里开始、哪里失败、怎样恢复，并且不把隐私资料交给维护者。

## 发布前 P0：必须完成

1. **明确许可证与角色边界**：本项目编排层已经选择 Apache-2.0 标准开源许可证。继续把纯本地开源、官方支持、代制作和云端服务分开说明；代码许可证、模型/素材许可证、商用责任和无托管声明也分开。
2. **首次启用向导**：第一次调用只提供手册和资料表两个可点击文件；用户填完简洁版或专业版后复制全文回传，再建立长期本地资料库和就绪状态。
3. **预检而非中途失败**：开工前检查操作系统、Python/Node/ffmpeg、GPU/显存、模型、字体、磁盘空间、网络、四个阶段 Skill 与授权状态，并给出可执行修复建议。
4. **无真人隐私演示项目**：用明确可再分发的合成或授权素材演示两种用户场景及其四种内部入口，附预期文件树、耗时区间、显存档位和结果截图。
5. **本地优先隐私**：默认不开遥测、不上传身份资产、不记录密钥；`.private/`、日志脱敏、删除/撤回路径随包提供。
6. **可恢复状态机**：每一阶段写哈希、输出、确认和失败原因；断电或报错后从最后一个有效交接点恢复，不重复花费已完成的模型调用。
7. **兼容性矩阵**：列出已测试的系统、GPU、模型/提供商版本、视频格式和阶段 Skill 版本；未测试组合标记为实验性。
8. **可读错误码**：错误同时给出“发生了什么、哪个文件/阶段、是否安全重试、用户下一步”，不只输出堆栈。
9. **自动化校验**：对两种用户场景、四种内部入口、Profile schema、`needs_update` 版本回退、私有文件泄漏、交接哈希、未授权第三方、高风险冒用、删除标识要求及封面/成片交付清单建立 CI 测试。
10. **真实预期说明**：公开样片硬件、耗时、成本、模型版本与已知缺陷；不承诺所有背景、人物或语言都达到同等效果。

## P1：提高首次成功率

- 完善本地向导：自动计算可用入口、读取每条 `task-order.json`，并在 Profile 需要重新校准时给出原因和最小补做项。
- 做“素材体检报告”，用通过/警告/拒收和具体时间点告诉用户为什么要重录。
- 为不同 TTS、口型模型和包装引擎定义适配器接口，不把一家提供商参数写进总控。
- 提供低配/标准/高配三档执行策略和估算，不改变质量底线，只改变分段、缓存和等待时间。
- 所有 Profile 和交接物带 schema 版本，升级时提供迁移脚本和回滚说明。
- 建立失败样例库：错误背景、遮嘴、镜头运动、发音误读、第一字被封面覆盖等都给出对照。
- 建立安全测试样例：本人合法用途应通过；“网上找的明星照片”“帮我冒充客服收验证码”“不要 AI 标识”等应在生成前停止，并给出不含绕过办法的说明。

## P2：形成社区生态

- Issue 模板自动收集系统信息、Profile 脱敏摘要、阶段、错误码和可公开日志，禁止用户误传真人母片或密钥。
- 用版本化适配器目录接收社区贡献；核心闸门、授权和 QA 不能被第三方适配器静默关闭。
- 提供可选、匿名、聚合遥测，默认关闭。只统计入口、失败阶段、耗时区间和是否通过，不采集文案、音频、肖像、链接或文件名。
- 发布变更日志、兼容性声明、迁移指南和安全公告；重大配置变化使用语义化版本。
- 托管云端作为另一个产品评估；只有隐私、合规、安全和运维能力成熟后再提供。

## 建议衡量指标

- 从安装到第一个内部样片的中位时间。
- 两种用户场景及四种内部入口的一次通过率与最常见失败阶段。
- 重录率、音频首次三选一后的返工率、画面 QA 通过率。
- 因恢复机制节省的重复生成次数。
- 用户对文案贴合度、声音自然度、画面稳定度和包装完成度的分项评分。

指标必须匿名、聚合、主动选择加入。没有遥测时，也可用自愿 Issue/问卷统计，不能以“改进产品”为由收集真人素材。
