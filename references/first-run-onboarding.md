# 安装后首次启用与本地建档

## 为什么不在安装瞬间自动收集资料

多数 Skill 安装器出于安全原因不会在安装完成时自动执行项目代码，也不应在用户尚未选择工作目录前采集声音和肖像。可靠做法是：

1. 安装页或发布说明先告诉用户“首次使用会建立本地资料库”。
2. 第一次调用静默完成发行文件完整性校验并准备两份客户文档；四阶段运行预检推迟到用户回传资料或实际发起制作任务后、进入相关生产阶段前执行。
3. 预检后检查用户工作区的 `profiles/onboarding-status.json`。
4. 文件不存在时进入首次启用向导；用户也可手动运行 `python scripts/init_user_workspace.py <工作区>` 创建骨架。
5. 已建档后读取 `profiles/asset-center.json` 显示四张资产卡，不重复询问稳定资料。

首次调用先运行 `python scripts/prepare_first_use_docs.py <当前活动工作区>`，把 Skill 安装目录中的 `数字人完整流程.md` 和 `开始使用前请先填写.md` 复制到工作区内版本化的 `数字人完整流程资料/` 目录。随后严格逐字发送脚本输出的三段欢迎语和两个工作区绝对文件链接，不在聊天中展开正文。不得直接链接 `.codex/skills/`，也不得自行拼接或猜测路径；Codex 文件查看器可能无法打开工作区外文件。除两个链接目标外，不得改写或追加任何内容。不得显示版本号、发行校验、工作区初始化、四阶段绑定、运行配置或端到端状态。前者解释数字人全流程和三种分别制作方式；后者包含简洁版和专业版资料表。初始化脚本仍会在正式建立新用户工作区时复制两份留存文档，并在 `forms/` 建立创作者资料简洁版、专业版和合法使用授权声明。

## 首次启用只做一个选择

首次引导不询问用户在“数字人全流程 / 分别制作”之间二选一，也不要求用户预先选择启用哪些任务能力。让用户在资料文档中选择基础信息简洁版或专业版，填写后复制所选版本的全部文字并发送回聊天。仅当用户明确要求访谈代填时，才逐项提问。

创作者资料回传并建档后，两种使用场景和三个独立模块都保持可用。声音、形象、包装资料在用户第一次实际进入对应模块时再收集，不要强迫“只想包装现成视频”的用户录声音，也不要让“只想二创”的用户提前上传肖像。

## 首次启用顺序

### 0. 环境与角色

1. 说明默认本地运行、维护者不接收上传。
2. 选择工作区；模块能力不由用户在首次引导中永久二选一。
3. 静默检查发行文件，运行 `prepare_first_use_docs.py` 把两份最新版客户文档准备到当前活动工作区；发现同版本副本被修改时另建目录，不覆盖用户内容。
4. 逐字发送脚本输出的固定欢迎语，以及两个指向当前活动工作区副本的可点击文件；不在聊天中展开正文或追加技术说明。
5. 四个阶段 Skill、运行环境、磁盘和模型的预检在用户回传资料或实际开始制作后执行；进入敏感素材采集或生产前必须完成。

### 1. 合法使用和人物关系

1. 用户说明本人/第三方、用途、平台、商业属性和最终发布者。
2. 完成合法使用声明；第三方准备分项授权证据。
3. 证据保存在 `.private/`，公开状态文件只保存匿名 ID、状态和哈希。

### 2. 创作者资料

1. 用户在资料文档中选择简洁版或专业版。
2. 用户填写后复制所选版本的全部文字并发送回聊天；只有用户要求时才改用语音或逐项访谈。
3. 简洁版逐项作答，且可选项写“无 / 暂无”，即达到建档要求；不得拿专业版或开工资料清单追加第二套问题。专业版同样不要求再填简洁版。
4. 用户回传所选版本本身即表示要求建立个人资料；不再要求回复“确认按此建档”。直接写入 `profiles/creator-profile.md`，状态变为 `ready`。
5. 动态事实默认在每条制作时核验公开来源；资料默认仅在本机长期复用。只有用户主动要求时才改为仅当前项目、修改或删除，不把这两项作为补充问卷。
6. 只有必填项真正留空、答案矛盾或涉及不能安全推断的资质与授权时，才针对那个具体缺口提问并附示例；不让用户重填整份资料。
7. 明确告诉用户：个人资料已建立，数字人全流程和分别制作已经同时可用，可直接发送本次输入并说明目标。

### 3. 第一次使用数字人音频时建档

完整执行 [数字人音频首次建档](audio-onboarding.md)：参考声录制 → 授权 → 体检 → 模型适配 → 同文案三风格盲听 → 验证文本 → 冻结 `voice-profile.json`。

### 4. 第一次使用数字人画面时建档

1. 录制前发送检查清单。
2. 用户录制并本地保存参考视频。
3. 完成授权和素材体检，写 `avatar-source-qa.json`。
4. 使用已批准的校准音频做 8–30 秒内部样片，检查口型、动作和循环；用户确认后冻结人物模板哈希。

### 5. 第一次使用剪辑包装时

用户提供有权使用的待包装视频即可进入素材检查。固定版式、字幕、封面、色彩和内部制作规则由 Skill 自动执行，不要求客户在首次引导中填写或选择；只有用户明确提供额外 Logo、声明或指定素材时才登记。

### 6. 就绪面板

把四类长期资料登记进 `profiles/asset-center.json`。该文件只保存 Profile 路径、版本、状态和哈希；原始声音、人物视频、授权证据和密钥仍保存在 `.private/`。向用户显示：

```text
创作者资料：ready / pending / not_selected
数字人音频：ready / pending / needs_recalibration / not_selected
数字人形象：ready / pending / needs_recalibration / not_selected
剪辑包装资料：ready / pending / not_selected
合法使用声明：ready / expired / blocked
可以开始的入口：full / from_script / from_audio / packaging_only
还缺什么：具体资料和下一步
```

首次新建工作区后，所有任务都从资产中心读取可复用 Profile。不得为每条视频重复复制声音参数、人物模板或品牌素材。

## 用户修改意见

首次初始化还会创建 `feedback/` 下四个独立文件，分别记录二创、数字人音频、数字人形象和剪辑包装反馈。每条意见都区分“仅本条 / 系列偏好 / 长期规则”；只有用户明确确认的长期规则才能更新以后任务。

## 长期资料与每条视频资料

### 通常只建一次

- 创作者职业、受众、案例、表达偏好和禁用项。
- 声音授权、参考声、所选音频风格、节奏参数、发音词典。
- 肖像授权、参考视频、人物裁切和素材 QA。
- 品牌、Logo、字体、色彩、CTA、封面人物图。

### 每条视频都要提供或确认

- 来源链接/原始资料/最终文案之一。
- 本条用途、平台、商业属性和目标时长；与长期声明一致时可简短确认。
- 动态事实、专有词新增读法、真实界面/录屏和本条指定素材。
- 文案、完整音频、完整画面三次确认及最终 QA。

## 重新校准与复核规则

- 换声音人物、模型版本、参考声或语言：数字人音频变为 `needs_recalibration`；旧声音文件和旧 Profile 继续作为历史版本保留。
- 换人物视频、画幅、脸部裁切或肖像授权：数字人形象变为 `needs_recalibration`；旧人物视频不视为损坏。
- 职业、资质、受众或长期内容定位实质变化：创作者资料需要复核。
- Logo、品牌名或包装要求变化：包装资料变为 `needs_review`，不重做声音和形象。
- 每次启动先显示需要重新校准或复核的原因，禁止静默把旧 Profile 用到不匹配的新组合。
