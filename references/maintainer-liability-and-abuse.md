# 开源维护者责任边界与滥用处理

> 本文件是产品和安全架构建议，不替代具体司法辖区的律师意见。不能用一句“一切与作者无关”排除法律规定不得排除的责任。

## 先判断你扮演什么角色

| 模式 | 维护者实际行为 | 风险与义务方向 |
|---|---|---|
| 纯本地开源 | 只发布代码/Skill；不接收素材、不提供算力、不代生成、不代发布 | 相对最低，但不是绝对为零；仍要避免宣传违法用途、预置滥用能力或明知后继续帮助 |
| 通用社区支持 | 只回答安装、兼容和普通错误；不接收真人母片 | 比纯发布略高；遇到可疑用途立即停止针对性支持 |
| 代制作/远程调试 | 接收文案、声音、肖像并替用户生成 | 已直接参与具体处理，必须核验授权、目的、内容和标识，不能仅靠免责声明 |
| 云端/SaaS/API | 维护者接收输入、提供算力、账户、下载或发布能力 | 可能进入深度合成服务提供者、技术支持者和个人信息处理者等更高义务场景，需要专项合规与运营体系 |
| 明知异常仍协助 | 已发现诈骗、冒用、侵权或规避标识迹象，仍调试、改造或提供替代方案 | 高风险；立即停止，不以开源或用户声明作为抗辩方案 |

## 推荐的公开声明

可以使用下述含义，但不要写成绝对免责：

```text
本项目以本地开源工具形式按现状提供。维护者不接收用户的声音、肖像或项目素材，不参与、不控制用户在其自有环境中的独立运行、生成和发布。使用者必须确保输入、授权、用途、发布和传播合法，并对其行为承担相应责任。本声明不排除适用法律下不得排除的责任，也不适用于维护者另行提供的托管、代制作、定制支持或明知违法侵权后继续协助的情形。
```

许可证中的“不担保”和责任限制有助于分配普通软件使用风险，但不是刑事、行政或侵权责任的万能豁免。Apache-2.0 本身也明确以“适用法律另有要求”等为边界：<https://www.apache.org/licenses/LICENSE-2.0.html>。

## 开源与用途限制的现实选择

1. **标准开源**：采用 Apache-2.0 等 OSI 认可许可证。优点是开源属性清晰；缺点是许可证不能按用途或行业限制用户。OSI 的开源定义要求不得限制特定使用领域：<https://opensource.org/osd>。
2. **负责任源代码可用**：加入禁止诈骗、冒用等用途限制。控制更强，但通常不能再宣称为 OSI 意义上的开源，应称“源代码可用”或“负责任开放”。
3. **推荐分层**：编排核心采用标准开源许可证并保持本地运行；官方品牌、官方托管、API、模型权重和代制作服务另行使用服务条款、可接受使用政策、授权核验和账户处置。这样不虚假宣传开源，也能控制你实际运营的部分。

用户仍然必须遵守法律，标准开源许可证没有“允许违法”的效果；只是维护者无法靠开源许可证控制每个离线副本。

## 代码开源不等于授权使用维护者本人

- 不把维护者本人的声音、脸部母片、姓名签名、账号品牌或商标放进公共 Skill 包。
- 代码许可证只授权代码，不自动授权任何人的肖像、声音、姓名或商标；在仓库和许可证说明中把这些资产明确排除。
- 演示项目优先使用无真实身份对应的合成人物，或专门取得可公开再分发授权的演示人物。
- 如果必须提供维护者本人的演示资产，应使用独立资产授权，严格限定是否允许生成、发布、商业使用和衍生内容；这与代码是否开源分开处理。
- 不允许第三方用项目名称、Logo 或维护者身份暗示其成片得到官方背书。

## 冒用防线

- 默认只允许“本人数字人”或有可验证授权的第三方。
- 第三方授权分开覆盖声音、肖像、嘴部驱动、剪辑、发布、商业使用、平台、期限和撤回；证据与项目编号绑定。
- 一张照片、公开视频、网上下载、聊天转述或单独勾选框均不足以证明第三方授权。
- 公众人物、未成年人、政府/司法/金融/媒体/客服身份以及收款、身份核验、新闻公告场景默认转人工法律复核。
- 成片强制保留显式和适用的隐式生成合成标识；拒绝删除或隐藏标识。
- 本地保存输入、授权、输出和确认的 SHA-256；不把真人素材上传给维护者充当审计。

## 发现滥用时

### 纯开源项目

- 停止针对该用途的技术支持，不帮助绕过闸门或寻找替代模型。
- 提供私密滥用举报渠道；公开 Issue 不接收身份证、真人母片或违法内容原件。
- 对官方仓库、文档和发布包中的安全缺陷及时修复并发布公告；无法控制已经复制到第三方设备的离线代码时如实说明。

### 托管或代制作

- 暂停生成、下载或发布；限制相关账户和令牌。
- 按最小必要原则保存事件记录，避免继续传播违法/侵权内容。
- 提供申诉、投诉和撤回渠道；按适用法律和主管部门要求处置或报告。
- 事件结束后复盘规则、日志和访问控制；不能用删除全部记录的方式掩盖问题。

## 中国境内重点依据

- 《互联网信息服务深度合成管理规定》禁止利用深度合成从事违法侵权活动；对服务提供者规定管理、审核、处置、投诉、授权提示、安全评估和标识等义务，并将部分义务延伸至技术支持者：<https://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm>。
- 全国人大法工委就 AI 换脸诈骗说明：为相关诈骗提供技术支持、帮助，可能依反电信网络诈骗法处罚，构成犯罪的还可能追究刑事责任：<https://www.npc.gov.cn/npc/c2/kgfb/202306/t20230626_430211.html>。
- 《反电信网络诈骗法》禁止为电诈提供支持或帮助，并对互联网服务提供者规定合理注意、监测识别和处置等要求：<https://www.npc.gov.cn/c2/c30834/202209/t20220902_319186.html>。
- 民法典第一千一百六十九条规定，教唆、帮助他人实施侵权行为的，可能承担连带责任：<https://www.spp.gov.cn/spp/ssmfdyflvdtpgz/202009/t20200922_483072.shtml>。

正式发布、提供云端或收费代制作前，应让熟悉网络安全、个人信息和平台治理的律师结合实际产品形态审查。
